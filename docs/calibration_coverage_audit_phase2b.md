Generated by `backend/scripts/calibration_coverage_audit.js`. Re-run after calibration backfills to update.

## 7. Pool Builder Notes for Session 2

Substring matching on the normalized product name produces false positives that will mislead `buildDynamicPool` if used naively. Session 2 needs stricter per-slug pattern logic. Observed false positives in this audit:

- **`kitchen_basics`** matches `pantene pro v` ("pan" substring), `smartypants kids` ("pan" substring), `andy pandy diapers`, `panera avocado toast`, `ihop buttermilk pancakes`. The intended matches are pans/skillets/spatulas/cookware — none of which appear in any of these. Needs word-boundary patterns (`\bpan\b`) plus negative filters for personal-care brands.
- **`bathroom_essentials`** matches `olaplex shampoo`, `crest toothpaste`, etc. because the spec's pattern list overlaps `bathroom_essentials` and `personal_care_kids` and `cleaning_supplies` — shampoo legitimately belongs to bathroom_essentials, but the audit double-counts it across slugs.
- **`bedding`** matches `gain dryer sheets`, `snuggle dryer sheets`, `method dryer sheets` because "sheet" appears as a substring. Real bedding is sheets-as-fabric, not dryer-sheets.
- **`pet_treats`** matches `stella and chewy's cat` because the brand name includes the keyword pattern for cat food → leaks into the treats bucket.

**Session 2 buildDynamicPool guidance:**
1. Use word-boundary regex (`\b...\b`) rather than naive `includes()`.
2. Define per-slug negative filters (e.g., kitchen_basics excludes any key containing `pantene`, `smartypants`, `panera`).
3. Cross-slug deduplication — a given calibration entry should only count toward one slug at pool-build time, even if multiple slugs would match. Pick the most specific.
4. Validation: after buildDynamicPool returns, log the per-slug count distribution. Any slug with 0 matches in the resolved pool means the prompt is asking for something the heuristic can't deliver — flag as a backfill or vocabulary signal.
